# MuinGuard 보안·SLO·운영 Runbook

## 1. SLO와 관측성

| 서비스 목표 | 측정 지표 | 초기 목표 | 경보 조건 |
| --- | --- | ---: | --- |
| 탐색 API 가용성 | 성공 응답 비율 | 99% 목표 | 5분 구간 오류율 급증 |
| 탐색 응답성 | P95 응답 시간 | 목표값은 부하 시험 후 확정 | 임계값 초과 지속 |
| 지도 장애 폴백 | 캐시/목록 전환 시간 | 10초 이내 목표 | 폴백 실패 |
| 긴급 제보 알림 | 제보→알림 시간 | 60초 이내 목표 | 미전송·재시도 초과 |
| 자동 승인 안전성 | 규칙 오류 시 공개 건수 | 0건 목표 | 규칙 오류·자동 공개 발생 |

목표값과 실제 값은 별도로 기록한다. SLO는 파일럿 부하·운영 인력에 따라 조정한다.

### 필수 로그 필드

`request_id`, `task_id`, `organization_id`, `place_id`, `actor_role`, `agent`, `attempt`, `dependency`, `fallback_used`, `outcome`, `duration_ms`.

비밀번호, 인증서 원문, 카드정보, 제보 사진 URL의 서명값, 사용자 연락처 원문은 로그에 남기지 않는다.

## 3. 개인정보·정책 출시 게이트

- 개인정보 처리방침과 수집·이용 동의 화면을 제공한다. 개인정보 처리방침의 수립·공개는 개인정보 보호법 제30조의 요구사항이다. [국가법령정보센터](https://www.law.go.kr/LSW/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1025127653)
- 전화번호·위치·사진·사업자 인증 자료는 서비스 목적에 필요한 최소 범위로만 수집한다.
- 사용자 제보 사진에는 제3자의 얼굴·차량번호 등 개인정보가 포함될 수 있으므로 신고·마스킹·삭제 절차를 제공한다.
- 실제 유료 구독·예약·결제 운영 전에는 사업자등록, 통신판매·소비자 보호, PG 계약, 세무·환불 정책을 전문가와 확인한다. 통신판매업 신고 안내에는 사업자등록증명 확인 항목이 포함된다. [정부24](https://www.gov.kr/mw/AA020InfoCappView.do?CappBizCD=11300000006)

## 5. 장애 Runbook

### 지도/장소 API 장애

1. 모니터링에서 timeout/5xx 증가 확인
2. `dependency=map` 로그와 캐시 최신 시각 확인
3. 최대 2회 재시도 후 캐시 목록/주소 결과로 폴백
4. 사용자에게 지도 제한·정보 확인 시각을 안내
5. 복구 뒤 폴백 사용 건수와 복구 시간을 보고서에 기록

### 자동 승인 규칙 오류

1. 모든 신규 등록을 `PENDING_REVIEW`로 안전 전환
2. 규칙 버전·입력 검증·중복 검사 장애를 확인
3. 관리자에게 미처리 등록 목록 알림
4. 수정·테스트 후 새 규칙 버전 배포
5. 영향받은 장소의 공개 상태와 감사 로그를 검토

### 긴급 시설 제보 알림 실패

1. 알림 작업의 시도 횟수·오류 코드 확인
2. 백오프 재시도 실행
3. 실패 시 조직 대표/관리자 대체 채널로 알림
4. 대시보드 미처리 경고를 유지
5. 처리 후 제보·알림 타임라인을 기록

### 개인정보 또는 권한 침해 의심

1. 해당 세션·토큰을 회수하고 관련 접근을 제한
2. 감사 로그·영향 범위를 보존
3. 민감 데이터 노출 여부를 판단하고 내부 책임자에게 에스컬레이션
4. 법적 통지·신고 필요 여부는 개인정보 책임자·전문가와 확인
5. 원인 제거, 재발 방지 테스트, 사후 보고서 작성

## 6. 백업·복구·변경 관리

- DB 백업 주기, 복원 테스트 주기, 보관 기간은 운영 환경 확정 후 문서화한다.
- 스키마 변경은 마이그레이션으로만 수행하고, 롤백 계획과 호환성 검사를 포함한다.
- Production 변경은 PR 리뷰, CI 통과, 배포 승인, readiness 확인을 거친다.
- 장애 주입·테스트 API는 demo/staging에서만 허용하고 production에서는 비활성화한다.
