# MuinGuard 출시 준비 운영 설계서

> 본 문서는 데모를 실제 파일럿과 공개 서비스로 전환할 때의 운영 기준이다. 법률·세무·결제 계약의 최종 판단은 출시 전 전문가 및 관할 기관 확인이 필요하다.

## 1. 출시 단계와 의사결정 게이트

| 단계 | 사용자 범위 | 제공 기능 | 출시/확장 게이트 |
| --- | --- | --- | --- |
| Demo | 팀·심사자 | P0 전체, 샘플 데이터 | 장애 시연·통합 테스트 통과 |
| Closed Pilot | 초청 사업자 3~5곳 | P0 + 운영자 피드백 수집 | 사장 등록 성공률·제보 처리 흐름 검증 |
| Public Beta | 제한 지역·일반 이용자 | 검증된 장소 탐색·시설 제보 | 개인정보·신고·지원 체계 준비 |
| Commercial | 실제 유료 사업자 | P1 구독·예약 문의 | 사업자등록·약관·결제 계약·환불 정책 검토 완료 |

**Go/No-Go 원칙:** P0의 검색, 제보, 다점포 권한, AutoHealing이 안정화되기 전에는 결제·실시간 예약을 출시하지 않는다.

## 2. 사장 온보딩과 장소 승인 운영

### 사장 온보딩 흐름

```text
사장 회원가입 → 조직 생성 → 지점/장소 입력 → 사업자 인증 제출
→ Approval Rule Engine 평가 → 자동 공개 또는 검토 대기
→ 공개 후 정보 확인 주기 안내 → 시설 제보·운영 대시보드 사용
```

### 자동 승인 정책

| 검증 항목 | 자동 승인 조건 | 실패 시 |
| --- | --- | --- |
| 사업자 인증 | 인증 정보가 제출·검증됨 | 검토 대기 |
| 필수 정보 | 장소명·주소·좌표·전화·운영시간·대표 사진 | 누락 필드 안내 |
| 업종 필수 정보 | 숙소 체크인 안내 등 카테고리별 요건 충족 | 검토 대기 |
| 중복 검사 | 주소·전화·좌표 유사 장소가 없음 | 중복 후보와 함께 검토 대기 |
| 정책 검사 | 금지어·비정상 연락처·악성 이미지 신호 없음 | 검토 대기 |

- 자동 승인 규칙은 버전 번호를 갖고, 변경 권한은 관리자에게만 부여한다.
- 규칙 엔진 오류 시 기본값은 **공개 보류(PENDING_REVIEW)** 다.
- 자동 승인·수동 승인·반려·정지에는 근거와 변경자를 감사 로그에 남긴다.

### 정보 신뢰도 운영

- 운영자 인증, 출처, 최종 확인일, 검증 상태를 장소 상세에 공개한다.
- 장소 정보는 정책상 정한 재확인 기한이 지나면 ‘확인 필요’로 표시하고 사장에게 갱신 요청을 보낸다.
- 이용자 제보는 즉시 공개 정보로 덮어쓰지 않고, 운영자·관리자 검토 상태를 거친다.

## 3. 고객 지원·시설 장애 운영

### 심각도 정의와 목표

| 등급 | 예시 | 초기 응답 목표 | 처리 목표 | 에스컬레이션 |
| --- | --- | ---: | ---: | --- |
| P1 긴급 | 출입 불가, 결제 전면 장애, 안전 위험 | 10분 | 4시간 | 지점 담당자 → 대표 |
| P2 높음 | 핵심 키오스크 기능 장애, 객실 체크인 지연 | 30분 | 24시간 | 지점 담당자 → 운영 관리자 |
| P3 보통 | 청결·안내 정보·재고 제보 | 4시간 | 72시간 | 지점 담당자 |
| P4 낮음 | 개선 제안·오탈자 | 1영업일 | 백로그 | 운영팀 |

> 위 수치는 파일럿 운영 목표다. 실제 약속 SLA로 외부 공개하기 전에는 인력과 계약 기준을 검증한다.

### 제보 생명주기

```text
RECEIVED → ASSIGNED → IN_PROGRESS → RESOLVED → CLOSED
                 └→ DUPLICATE / REJECTED
```

- `RESOLVED`: 담당자가 조치를 완료했다고 표시한 상태
- `CLOSED`: 제보자 확인 또는 운영 정책상 종료된 상태
- 고심각 제보는 알림 실패 시 조직 대표에게 대체 알림하고, 대시보드에 미처리 경고를 남긴다.

## 4. 데이터 확보와 지역 확장

### 초기 데이터 원칙

1. Demo는 명확히 표시된 샘플 데이터만 사용한다.
2. 파일럿은 사장이 직접 등록·인증한 장소를 우선한다.
3. 공개 정보를 사용하더라도 출처·사용 권한·최종 확인일을 기록한다.
4. 허가 없는 사진, 리뷰, SNS 콘텐츠를 복제하지 않는다.

### 확장 순서

| 순서 | 지역/대상 | 이유 | 검증 지표 |
| --- | --- | --- | --- |
| 1 | 한 개 생활권·지점 2~5개 | 운영 흐름 관찰이 쉽다 | 등록 완료율·제보 처리 시간 |
| 2 | 수도권 내 동일 업종 다점포 | 다점포 가치 검증 | 주간 활성 지점·반복 장애 감소 |
| 3 | 숙소+무인샵 혼합 | 수요 측 탐색 확대 | 검색→상세 전환·길찾기 클릭 |

## 5. 분석 이벤트 설계

| 이벤트 | 발생 조건 | 핵심 속성 | 사용 목적 |
| --- | --- | --- | --- |
| `search_performed` | 위치/지역 검색 실행 | category, radius, region | 탐색 수요 |
| `place_viewed` | 장소 상세 진입 | place_id, source | 상세 전환 |
| `directions_clicked` | 길찾기 선택 | place_id | 방문 의도 |
| `call_clicked` | 전화 선택 | place_id | 문의 의도 |
| `incident_created` | 시설 제보 제출 | category, severity, place_id | 운영 품질 |
| `incident_assigned` | 담당자 배정 | organization_id, elapsed_ms | 대응 속도 |
| `place_auto_approved` | 자동 승인 | rule_version, elapsed_ms | 온보딩 품질 |
| `fallback_used` | AutoHealing 폴백 | dependency, strategy | 복구 품질 |

분석 이벤트에는 불필요한 원문 연락처·제보 본문·정확한 위치를 넣지 않는다.

## 6. 수익·비용 관리 원칙

- **수익 가설:** 대표가 다점포 현황 확인·장애 제보 관리에 쓰는 시간을 줄이고, 유입·운영 품질을 확인하게 하면 Pro/Business 구독 의향이 생긴다.
- **가격 검증:** 가격을 먼저 고정하지 않고, 파일럿 인터뷰에서 기존 운영 방식·절감 시간·지불 의향을 조사한다.
- **월 비용 계산식:** 인프라(서버+DB+캐시+스토리지) + 외부 API(지도·알림·AI) + 지원 운영 시간 + 결제/도메인 비용.
- **비용 경보:** API 호출량, 이미지 저장량, AI 토큰, DB 연결 수에 예산 상한 알림을 설정한다.
- **단위 경제성:** 유료 사업자 1곳당 월 매출 대비 인프라·지원 변동비를 추적한다.

## 7. 출시 수용 기준

| 기능 | 수용 기준 |
| --- | --- |
| 장소 탐색 | 위치 권한 거부 시에도 지역 검색으로 결과를 보여준다. |
| 사장 등록 | 조건 충족은 AUTO_APPROVED, 조건 미충족은 PENDING_REVIEW로만 처리된다. |
| 권한 격리 | 다른 조직의 장소·제보·통계 요청은 403이고 감사 로그가 생성된다. |
| 시설 제보 | 제보 생성은 멱등하며 담당자 배정·상태 이력이 보존된다. |
| 지도 장애 | 외부 지도 API 실패 시 캐시 목록 또는 안전한 안내가 제공된다. |
| 알림 장애 | 고심각 제보 알림 실패 시 재시도·대표자 폴백이 기록된다. |
| 개인정보 | 서비스 목적에 필요한 최소 정보만 수집하고, 처리방침 화면을 제공한다. |
