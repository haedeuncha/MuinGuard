# MuinGuard 95점 목표 품질 보완 계획

## 1. 목표

점수를 보장할 수는 없지만, 평가 항목별로 심사자가 직접 확인할 수 있는 증빙을 준비해 95점 수준의 완성도를 목표로 한다. 핵심은 기능의 개수가 아니라 **일관된 서비스 경험, 실제 자동 복구, 정량 결과, 안정적인 발표**다.

## 2. 평가 항목별 보완 전략

| 평가 항목 | 배점 | 고득점 설계 | 반드시 보여줄 증빙 |
| --- | ---: | --- | --- |
| 기획·목표 달성 | 25 | 무인 운영 공간 이용자와 사업자 대표의 문제를 한 서비스로 연결 | 문제 정의, 사용자 흐름, MVP/확장 범위 |
| 서비스 완성도 | 35 | 모바일 지도 검색·상세·제보·사업자 대시보드의 끝까지 이어지는 흐름 | 배포 URL, 테스트 계정, 실제 데이터, 반응형 화면 |
| 수행 과정·개선 | 20 | 장애 주입 실패도 기록하고 재시도·캐시·대체 알림으로 개선 | 전후 로그, 커밋, 이슈, 복구 지표 |
| 발표 전달력 | 20 | 정상 → 장애 → 자동 복구 → 배포 차단 → 지표 순서의 스토리 | 20분 시연 대본, 백업 영상, 캡처 |

## 3. MVP 동결 원칙

발표 전에는 다음 네 흐름을 먼저 완성한다.

1. 현 위치 기반 검색 → 카카오맵 → 장소 상세
2. 고객 시설 장애 제보 → AI 분류 → 담당 지점 처리
3. 사업자 다점포 대시보드 → 지점 비교 → 권한 분리
4. 지도 API 장애 → 재시도 → 캐시 폴백 → Critic 검증 → 로그

실시간 객실 재고, 실결제, 복잡한 추천 모델은 위 흐름이 모두 안정화된 뒤에만 확장한다.

## 4. 정량 목표와 실제 보고 방식

| 지표 | 목표 | 실제 결과 기록 방법 |
| --- | --- | --- |
| 핵심 E2E 시나리오 | 100% 통과 | CI 통합 테스트 결과 |
| 장애 시나리오 | 4개 이상 수행 | Scenario ID별 표 |
| 자동 복구율 | 80% 이상 목표 | 성공/전체 계산식과 원시 로그 |
| 지도 API 폴백 | 10초 이내 목표 | 시작/종료 타임스탬프 |
| 심각 제보 알림 | 60초 이내 목표 | 생성/알림 시간 로그 |
| 보안 격리 | 타 조직 데이터 0건 노출 | 403 권한 테스트 |

목표를 달성하지 못한 경우에도 결과를 숨기지 않고 원인과 다음 개선을 설명한다.

## 5. 발표 시연 안전장치

- 운영과 분리된 demo 환경, 고정된 테스트 계정·지점·장소 데이터를 사용한다.
- 장애 주입은 테스트 환경에서만 실행하고 시작 전 상태를 복구한다.
- 외부 API·네트워크 실패를 대비해 1~2분짜리 백업 영상을 준비한다.
- API 키·전화번호·개인정보·실제 결제 정보는 화면 공유 전 마스킹한다.
- 발표자는 20분 중 라이브 시연을 8~10분으로 제한하고 나머지는 구조·지표·개선 설명에 사용한다.

## 6. 제출 직전 품질 게이트

- [ ] 배포 URL에서 모든 핵심 흐름이 동작한다.
- [ ] 장소 데이터에 출처·확인일·검증 상태가 있다.
- [ ] 조직/지점 권한 격리 테스트가 통과한다.
- [ ] 4개 이상 장애 시나리오의 실제 로그·캡처가 있다.
- [ ] 재시도 횟수와 종료 조건이 코드·문서·로그에서 일치한다.
- [ ] 테스트 실패 시 배포가 중단되는 CI 실행 결과가 있다.
- [ ] 발표 자료의 수치와 보고서의 수치가 일치한다.
- [ ] 실패 사례와 개선 내용이 최소 1건 이상 기록되어 있다.
